> ツールバーのセグメント・丸型アイコンボタンの1pt輪郭は
> [ADR 0016](0016-ui-refresh.md) で廃止した。`CONTROL_OUTLINE` は
> 明るい色のカラースウォッチの縁にだけ残している。

# Context

ADR 0006 は M3 Baseline の `outline` (`#79747E`) をコントロールの境界にそのまま使っていた。
ツールバーでは描画ツール6個と線幅3個のセグメントが横に連なり、1pt の輪郭が長い直線として
目に入る。丸型アイコンボタンと白スウォッチの縁も同じ色で、輪郭がアイコンやラベルより
目立ち、ツールバー全体が実際より重く見える（「UIの枠線が濃すぎる」）。

一度は灰色寄りの `#9A94A2` まで明るくしたが、まだ濃く、ラベンダーの背景に対して
枠線だけが灰色に見える（「まだ濃い」「若干背景の紫に寄せたほうがいい」）。

一方、部品の境界を消すと押せる範囲が分からなくなる。面の区切り（`outlineVariant`）と
部品の境界（`outline`）という M3 の役割分担は維持したい。

# Decision

部品の輪郭専用のトークン `CONTROL_OUTLINE` (`#BCAEC7`) を追加し、次の縁に使う。

- セグメントボタン（描画ツール・線幅）
- 丸型アイコンボタン（元に戻す・やり直す、有効時）
- 明るい色のカラースウォッチの輪郭

色相は背景の `surfaceContainer` (`#F3EDF7`) と同じ紫寄りに揃え、白背景に対する
コントラストを 4.5:1 から約 2.1:1 へ落とす。線幅は 1pt のまま変えない。
分割線・キャンバス外周・ツールバー下端・無効状態のボタンは `outlineVariant` のまま。

不採用: 灰色のまま明るくする案（背景の紫から浮いて枠線だけが目立つ）、
`outlineVariant` を部品の輪郭にも使う案（分割線と同じ濃さになり、ボタンの境界が
背景に溶ける）、輪郭を 0.5pt に細くする案（等倍表示でにじみ、境界がまだらになる）、
`outline` の値を直接変える案（M3 の参照値を失い、強調したい別の箇所に使えなくなる）。

# Consequences

## Pros

- 枠線が背景と同系色になり、面から浮かずに馴染む。
- 輪郭が軽くなり、アイコンとラベルが主役になる。
- トークンの役割（面の区切り / 部品の境界）を変えずに色だけを差し替えられる。

## Cons

- 部品の境界は白背景で約 2.1:1、ツールバー背景 (`#F3EDF7`) に対しては約 1.8:1 まで下がり、
  低コントラスト環境では押せる範囲が以前より見えにくい。
- 選択中のセグメントは塗り (`secondaryContainer` `#E8DEF8`) と背景の差が小さいため、
  輪郭を薄くすると選択状態の手掛かりが弱くなる。
- M3 Baseline の値から外れるため、トークンを見直すときはこの差分を意識する必要がある。
