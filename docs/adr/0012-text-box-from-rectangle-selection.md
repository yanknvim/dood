# Context

テキストはクリック位置に既定幅 260pt の入力欄を開き、確定後は折り返さずに描いていた。
次の要望が出た。

- テキストの位置を矩形で選択し、その中に収まるテキストボックスを作りたい。
- 入力中の見た目と、確定後の見た目を一致させたい。

SPEC の非目標には「自動折り返し」があり、そのままでは実現できない。また、入力欄は
260pt で折り返す一方、確定後の描画は折り返さないため、長い行はキャンバスの右端で
切られていた。

# Decision

テキストツールのドラッグで指定した矩形を、そのままテキストボックスとして扱う。

- 押下位置を始点、ドラッグ中の位置を終点とする。幅 40pt・高さ 30pt 以上ならボックスを作り、
  それ未満はクリック扱いにして既定幅の入力欄を開く。
- 入力欄は選択した矩形いっぱいに置き、文字は矩形幅（入力欄の内側余白を除く）で折り返す。
- `Item::Text` に `wrap_width: Option<f32>` を持たせ、確定後も同じ幅で折り返して描く。
  折り返しは `LayoutJob` の `break_anywhere = true` で行う。
- ドラッグの始点は `Response::drag_started` の位置ではなく、`PointerState::press_origin`
  から取る（しきい値を超えるまで数 px ずれるのを防ぐ）。
- 縦方向はボックスからはみ出してもクリップせず、下に伸びる。禁則処理はしない。

不採用: 文字サイズをボックスに合わせて自動縮小する案（太さの段との連動が崩れる）、
折り返さずにクリップする案（選択した箱の意味がなくなる）。

# Consequences

## Pros

- 先にレイアウトを決めてから文字を収められる。
- 入力中と確定後で折り返し幅が一致する。
- クリックだけの従来操作も残る。

## Cons

- 長い英単語は単語の途中で切れる。
- 文字が縦にあふれると、選択した箱より下に伸びる。
- 折り返しはキャンバス全体ではなく、テキストボックスごとの幅になる。
