# Context

M3 ツールバー（ADR 0006）は全コントロールを1行に並べていたため、ウィンドウを狭くすると
右側のコピー・保存が画面外にはみ出して操作できなかった（最小幅は 480pt）。

また、保存・コピーなどの結果表示をツールバー内にインラインで置いていたため、
長いメッセージ（保存先パスなど）がボタンを押し出し、しかも表示が消えずに残り続けていた
（「ここに出る表示が消えない 保存、読み込みなど」）。

キャンバス上にオーバーレイする案は、ADR 0002 のスクリーンショット切り出しに
写り込むため採用できない。

# Decision

1. ツールバーを**グループ単位の折り返し**にする。
   - グループは 描画ツール / カラーパレット / 太さ・文字サイズ / Undo・Redo / 消去 /
     コピー・保存。
   - 各グループの幅を実フォントの `Galley` から測り、`plan_toolbar` で行に詰める。
     グループは行をまたいで分割しない。
   - 幅が足りる広いウィンドウでは1行、狭いときは2段以上に折り返す。
   - コピー・保存は最終行の右端に右寄せし、入らなければ新しい行に置く。
2. ツールバーの下に**固定高さのステータスバー**を常設する。
   - メッセージが無いときは保存先パスを表示する。
   - メッセージは成功 3 秒 / エラー 6 秒で自動消去する。
   - `request_repaint_after` で、マウス操作が無くても期限どおりに消える。
   - ステータスバーはキャンバスの外にあり、スクリーンショットの切り出しに含まれない。

不採用: ツールバーをスクロールさせる案（見えないボタンが残り、スクラッチパッドには
向かない）、ステータスをキャンバスにオーバーレイする案（出力 PNG に写り込む）、
折り返さずにボタンだけ縮める案（タッチ領域が小さくなり押し間違える）。

# Consequences

## Pros

- 最小幅 480pt でも全ボタンが画面内に残り、クリックできる。
- ステータス表示がボタンの位置を動かさない。
- 自動消去により、古いメッセージがツールバーを占有し続けない。
- 常に保存先を確認できる。

## Cons

- ツールバーの高さが行数に応じて増え、狭いウィンドウではキャンバスが縦に小さくなる。
- ステータスバーが高さ約 22pt を常に使う。
- グループ幅を測るぶん、描画コードが少し増える（折り返し計算の単体テストで担保）。
