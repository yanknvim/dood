# Context

キャンバスの寸法をどう決めるかで、使い勝手と実装が変わる。

固定サイズ（例 1200×800pt）にすると、書き出しの寸法が毎回同じで扱いやすい。
一方、この Mac の画面は 1280×832pt なので、1200×800 のキャンバスはツールバーを足すと
画面に収まらず、等倍表示できない。縮小表示すると線が滲み、注釈の座標も画像とずれる。

スクリーンショットへの注釈では、元画像と等倍で対応していることが重要。

# Decision

キャンバスは**ウィンドウの内側サイズからツールバー行を除いた領域**とする。固定サイズは持たない。

- 座標はキャンバス左上原点の pt。ウィンドウをリサイズしても既存の描画の座標は変えない。
- 広がった分は余白、狭まった分はクリップ（モデルからは消さない）。
- 背景画像を貼り付けたときは、画像の実寸に合わせてウィンドウをリサイズする
  （画面に収まらない場合は縮小表示）。

不採用: 固定キャンバス＋フィット表示（等倍で描けない）、無限キャンバス＋パン/ズーム（v1 の範囲を超える）。

# Consequences

## Pros

- ウィンドウを広げるほど描く面積が増え、書き出しも大きくなる。操作が直感的。
- 出力＝見えている範囲なので、書き出し結果が予測できる。
- 背景画像を等倍で扱えるため、注釈の座標が画像の座標と一致する。

## Cons

- 出力サイズが可変で、毎回同じ寸法にはならない。
- ウィンドウを狭めると図の端が切れる（データは残るが、書き出しには入らない）。
- 座標を正規化していないため、将来ズーム機能を足すときは座標変換の導入が要る。
