# Context

手描きの図をコーディングエージェントに渡すための最小 GUI アプリを新規に作る。
要件は「マウスで描ける」「最低限の図形と文字と色」「クリップボードまたは PNG で出す」。
macOS（Apple Silicon）専用でよい。

GUI の選択肢は、egui/eframe、Tauri + HTML canvas、iced、GTK4 など。
フォント・IME・クリップボード画像の扱いが自前になるほど実装量が増える。

egui/eframe は 0.37.0（2026-10-15 リリース）が最新。ただし移行期で、
0.34.0 で `App::update` が廃止されて `App::ui` になり、0.37.0 でスクリーンショット API が
イベント方式からコールバック方式に変わった。ネット上の例は 0.33 以前の形が大半。

# Decision

`eframe = "=0.37.0"` を採用し、バージョンを `=` で固定する。
実装は `App::ui(&mut self, ui, frame)` を必須メソッドとする 0.37 系 API に合わせ、
API の参照は必ずタグ `0.37.0`（docs.rs と GitHub のソース）に固定する。

採用理由:
- `clipboard` / `system_fonts` / `wgpu` がデフォルトフィーチャで有効。クリップボード画像と
  日本語フォントが追加設定なしで手に入る。
- 0.37.0 でクリップボード画像の半透明色が暗くなるバグが修正済み。
- 単一バイナリで完結し、Web 資産（HTML/JS）を持ち込まずに済む。

不採用: Tauri（Web スタックの分だけ構成が重い）、iced（クリップボード画像と IME を自前で
繋ぐ必要がある）、GTK4（macOS での配布と見た目の相性が悪い）。

# Consequences

## Pros

- 依存が少なく、`cargo run` だけで動く単一バイナリになる。
- クリップボード画像・日本語フォント・IME がフレームワーク標準の範囲で済む。
- 描画は GPU（Metal）で、ペンの追従が軽い。

## Cons

- 0.37 系は API 移行期で、古いサンプルがそのままでは動かない。学習コストはドキュメント側に寄る。
- MSRV は 1.95。wgpu を含むため初回ビルドが重い（数十秒〜数分）。
- 0.38 以降で再度 API が変わる可能性がある。更新は「別の作業」として扱い、依存は勝手に上げない。
